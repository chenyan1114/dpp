鏈上授權簽名金鑰（did:ethr＋MetaMask）

MetaMask 帳戶 = 發證單位的 DID（由它付 gas）；頁面產生的金鑰 = 被授權的簽名鑰匙（不需要 ETH）。 授權 = 呼叫 registry 的 addDelegate(你的地址, "veriKey", 簽名鑰匙, 有效期)，之後用 #delegate-N 簽 VC； 撤銷 = revokeDelegate，撤銷後用它簽過的 VC 再驗證就會失敗。需要少量 Sepolia 測試幣。

尚未連接 MetaMask。

解析 DID 文件

DID 文件列出「這個 DID 授權了哪些金鑰」。did:key 由字串本身推導；did:ethr 由 ethr-did-resolver 讀 Sepolia 上 ERC-1056 registry 的鏈上事件組出（含委派金鑰、撤銷、owner 轉移、停用）。

上傳別處產生的 vc.json 也能驗：簽名照驗，claims 會跟目前表單比對，不合只記提醒。

    
簽名規格：DataIntegrityProof，cryptosuite 依 issuer 的 DID 方法而定。
      流程：先組 proof options → JCS 正規化 proof options 與文件 → 各取 SHA-256 → 串接後用 issuer 私鑰簽名 →
      proofValue 掛回文件。簽名後按「驗證」即做密碼學驗證；改任一字再驗就會失敗。

    
    
      
  • did:key → eddsa-jcs-2022（W3C 標準）：Ed25519 簽 64-byte 串接值，驗證用 DID 內的公鑰。
    • 
      
  • did:ethr → ecdsa-secp256k1-recovery-jcs-demo（教學用、非 W3C 標準）：
        secp256k1 簽串接值的 SHA-256，proofValue 為 65 bytes（r‖s‖recId）。驗證時從簽名回推出地址，
        再解析 issuer 的 DID 文件，找到 verificationMethod 指到的金鑰（#controller 或委派的 #delegate-N）比對地址
        （唯讀，不花 gas；連不上 RPC 就以「#controller = DID 地址本身」離線判定）。
